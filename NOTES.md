# Treadmill Control — состояние проекта

Android-приложение на Kotlin + Compose для управления беговой дорожкой
UNixFit-990x через Bluetooth Low Energy (профиль FTMS), с поддержкой
нагрудного пульсометра и автоматической регулировкой скорости по пульсу.

**Сборка:** GitHub Actions → артефакт `treadmill-debug-apk` (сейчас `archive: false`, скачивается сразу APK).
**Работает полностью офлайн** — разрешение `INTERNET` намеренно не запрашивается.

## BLE — детали

### UUID (в `Uuids.kt`)

- **FTMS Service:** `0x1826`
- **FTMS Control Point:** `0x2AD9` (или `0x2A66` — оба варианта поддерживаются)
- **FTMS Treadmill Data:** `0x2ACD` (notify)
- **FTMS Feature:** `0x2ACC` (read)
- **FTMS Status:** `0x2ADA`
- **Heart Rate Service:** `0x180D`, measurement `0x2A37`
- **FitShow proprietary:** `0xFFF0` (write — `0xFFF2`, notify — `0xFFF1`)

### Наша дорожка (UNixFit-990x, модуль `FS-E629DD`)

- **Протокол:** FTMS работает. FitShow proprietary — **не работает** (все команды игнорируются).
- **Скорость:** работает через `02 XX XX` (0x02 = Set Speed, XX XX — км/ч × 100).
- **Наклон:** работает через `03 XX 00`. **Принимает только целые %**. 0.5% игнорируется.
- **Стоп:** `08 01` (Stop/Pause) **игнорируется**. Работает только `02 00 00` (скорость 0).
- **Старт:** `07` работает, но belt иногда не начинает движение без предварительной установки скорости.
- **Команды иногда пропускаются** — приходится дублировать.
- **Control Point не отвечает** на команды — просто молчит, но команды выполняет.

### Логика отправки команд (`FTMSProtocol.kt`)

- **Отправители-корутины** с `collectLatest` — при быстрых нажатиях уходит только последнее значение.
- **Debounce 200 мс** — после последнего нажатия.
- **Дублирование каждой команды ×2** с интервалом ~60 мс — belt пропускает первую команду.
- **Confirm 800 мс**, **2 попытки** максимум.
- **`start()`** отправляет: контроль → скорость (≥1.0 км/ч) → `07`.
- **`stop()`** отправляет: контроль → `02 00 00` → `08 01` (belt реагирует только на первое).

### Определение дорожек (`BleManager.isTreadmillDevice`)

Показываются в списке, если:
1. Имя начинается с `FS-` (например, `FS-E629DD`)
2. Имя содержит `fitshow`
3. В рекламном пакете есть сервис `0x1826` (FTMS)

## Логика тренировки

### `WorkoutManager.kt`

- Состояние: `running`, `paused`, `finished`, `currentSegmentIndex`, `segmentElapsedSec`, `totalElapsedSec`
- **`start()`** — с нуля, `launchLoop()`
- **`pause()`** — отменяет job, сохраняет позицию
- **`resume()`** — снова запускает loop, восстанавливает текущий сегмент
- **`togglePause()`** — переключение
- **`stop()`** — полный сброс

### `MainViewModel.startWorkout(program)`

Порядок:
1. Проверка `isTreadmillReady()`, иначе — сообщение и выход
2. `protocol.start()` — запуск дорожки
3. `delay(600)` — дать belt время
4. `workoutManager.start(...)` — программа сама выставит скорость первого сегмента

### `MainViewModel.pauseWorkout()`

1. `workoutManager.pause()` — таймер встал
2. `protocol.stop()` — belt встал
3. Сообщение «Тренировка на паузе»

### `MainViewModel.resumeWorkout()`

1. Проверка подключения
2. `protocol.start()` — belt снова пошёл
3. `delay(500)`
4. `workoutManager.resume()` — таймер продолжился, команды скорости/наклона вернулись

### Авторегулировка по пульсу (`HeartRateController.kt`)

- Режим **TARGET** (целевой пульс) или **ZONE** (мин-макс)
- При превышении: скорость − stepKmh (0.5 км/ч по умолчанию)
- При недостатке: скорость + stepKmh
- Интервал 30 сек (настраивается)
- **Не работает, если `_targetSpeed.value <= 0.5`** — не поднимает скорость со стопа
- **Останавливается при потере дорожки**

## Настройки (SettingsStore)

| Поле | Назначение | По умолчанию |
|---|---|---|
| `protocol` | FTMS или FitShow | FTMS |
| `themeMode` | SYSTEM / LIGHT / DARK | SYSTEM |
| `manualWriteUuid` | Ручной UUID записи (для FitShow) | пусто |
| `manualNotifyUuid` | Ручной UUID уведомлений | пусто |
| `minSpeedKmh` / `maxSpeedKmh` | Границы скорости | 1.0 / 12.0 |
| `maxInclinePercent` | Максимальный наклон | 15.0 |
| `inclineStep` | Шаг кнопок наклона | 1.0 (belt не понимает 0.5) |
| `hrEnabled` | Автопульс вкл/выкл | false |
| `hrMode` | TARGET / ZONE | TARGET |
| `targetHr` | Целевой пульс | 130 |
| `zoneMin` / `zoneMax` | Зона пульса | 120 / 140 |
| `thresholdHigh` / `thresholdLow` | X / Y (допуск) | 5 / 5 |
| `intervalSec` | Интервал авторегулировки | 30 |
| `stepKmh` | Шаг изменения скорости | 0.5 |

  "name": "Интервальная тренировка",
  "description": "5 интервалов",

- **Поиск** по названию/описанию

- **Редактор сегментов:** ↑/↓/⎘/🗑 у каждого сегмента

### Редактор сегмента

- Имя, длительность (сек), скорость (км/ч), наклон (%)
- Числовые поля с фильтрацией ввода
- Парсинг чисел с запятой и точкой

## UI — раскладка

### Нижняя навигация (`AppNavHost.kt`)

4 вкладки через `HorizontalPager` — свайп влево/вправо или тап по иконке:

1. **Главная** (MainScreen)
2. **Программы** (ProgramsScreen)
3. **Журнал** (HistoryScreen)
4. **Настройки** (SettingsScreen)

Debug и About — **внутри Настроек** → карточка «Дополнительно». На главном — иконки нет.

### Главный экран (`MainScreen.kt`)

- Заголовок «Treadmill Control» по центру + **имя подключённой дорожки** (синим)
- Две плитки: **Дорожка** / **Пульсометр** с кнопками Подкл./Откл. и именем устройства
- Плитки **Скорость** / **Наклон** с кнопками −/+ (иконки, 34dp)
- Карточка метрик: Пульс, Время, Дистанция, Калории — **по центру ячеек**
- Карточка **Автопульс** с рабочим Switch и кнопкой «Настроить»
- Кнопки: **Старт / Стоп / ЭКСТРЕННАЯ ОСТАНОВКА**
  - Все три **дизейблятся**, если дорожка не в состоянии READY
- **Прокрутка:** сверху вниз, но контент сжат, чтобы обычно влезал

### Экран тренировки (`WorkoutScreen.kt`)

- Тёмная тема (обёрнут в `Surface(background)`)
- **Не прокручивается** — график пульса растягивается под свободное место
- Карточка прогресса: «Сегмент N/M: Имя», остаток времени, общий %
- Плитки **Скорость / Наклон** прямо на экране (управление во время тренировки)
- **График пульса** — 30 мин + текущее значение + целевой HR
- Метрики по центру: Время, Дистанция, Калории
- Кнопки: **Пауза / Продолжить**, **СТОП!**, **Сброс**, **ЭКСТРЕННАЯ ОСТАНОВКА**
  - «Пауза» → серая
  - «Продолжить» → зелёная
  - Дизейбл, если дорожка не READY

### Анимация чисел (`RollingText.kt`)

Используется на всех числах — плавно «прокручиваются» снизу-вверх при смене значения (180 мс).

### Тёмная тема (`Theme.kt`)

- Выбор в Настройках: Как в системе / Светлая / Тёмная
- Цвета Material 3, применяются на всех экранах
- Статус-бар тоже перекрашивается

## Журнал и статистика (`HistoryScreen.kt`)

**Вкладка «Список»** — все тренировки с датой, программой, длительностью, км, калориями, пульсом.

**Вкладка «Статистика»:**
- **Общая сводка:** всего тренировок, часов, км, ккал
- **Пульс:** средний / максимальный / лучший средний
- **Тренд** (при 4+ тренировках): сравнение среднего пульса первой и второй половины, стрелка ↓/↑ и оценка
- **Два графика:** средний пульс и максимальный пульс по датам

**Демо-данные:** ⋮ → «Загрузить демо-данные» — 20 тренировок за 10 недель с реалистичным трендом (пульс 155 → 135). Есть «Очистить журнал».

## Сборка и обновление APK

### `build.yml`

- Триггеры: push в `main`/`master`, ручной запуск
- Шаги: checkout → JDK 17 → Setup Gradle 8.6 → `gradle assembleDebug --no-daemon`
- **Артефакт без zip:** `archive: false`, `path: app/build/outputs/apk/debug/app-debug.apk`

### `build.gradle.kts` — версии

```kotlin
versionCode = 7      // ← увеличивать перед каждой сборкой для обновления «поверх»
versionName = "1.7"  // ← для красоты
```

### Обновление приложения без удаления

1. Увеличить `versionCode` в `build.gradle.kts` (7 → 8 → 9 …)
2. Push → дождаться Actions → скачать `app-debug.apk`
3. Открыть APK на телефоне → Android покажет **«Обновить»**
4. Все данные (программы, настройки, журнал) сохраняются

Удаление требуется, только если:
- вы не увеличили `versionCode`,
- или предыдущая версия была подписана другим ключом (например, локальная сборка из Android Studio).

### Ускорение сборки (`gradle.properties`)

```properties
org.gradle.caching=true
org.gradle.parallel=true
org.gradle.configuration-cache=true
```

Первая сборка после push — 4–5 мин. Повторные с теми же зависимостями — 2–3 мин. Это нормально.

## Решённые проблемы

- ❌ Belt игнорирует команду `08 01` (Stop) → ✅ используем `02 00 00` (скорость 0)
- ❌ Belt не понимает наклон 0.5% → ✅ округляем до целых
- ❌ Команды теряются → ✅ дублируем каждую ×2, debounce 200 мс
- ❌ HR-auto поднимал скорость после стопа → ✅ не поднимает, если `targetSpeed <= 0.5`
- ❌ Программа не стартовала с нуля → ✅ сначала `protocol.start()`, потом `delay(600)`, потом программа
- ❌ Debug-экран был на белом фоне → ✅ обёрнут в `Surface(background)`
- ❌ Кнопки Старт/Стоп/Экстренный без дорожки были активны → ✅ дизейбл, если не READY
- ❌ Таймер программы шёл без дорожки → ✅ автопауза при потере связи

## Диагностика

Если снова не работает наклон / скорость / программа:

1. Открыть **Debug** (Настройки → Дополнительно → Debug)
2. Повторить проблему
3. Нажать 💾 **Сохранить** → файл `treadmill_log_YYYY-MM-DD_HH-mm-ss.txt`
4. Открыть файл и скопировать содержимое в чат

В логе будет видно:
- Все сервисы/характеристики дорожки при подключении
- Какие команды отправлены (синие `->`)
- Что ответила дорожка (зелёные `<-`)
- Все ошибки
